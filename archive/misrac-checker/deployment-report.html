📌 1 · Overview
Q3 release procedures for the MISRA-C:2012 checker v2.1 rollout
ℹ️
What is being deployed
MISRA-C:2012 checker v2.1 is being promoted from staging to production CI across all embedded repositories. This procedure is deterministic and reversible via the rollback step in section 5.
⏱️ Release Summary

Promote the checker image to the shared CI registry, update the .github/workflows/misra.yml reference, and validate on a canary repo before fleet-wide rollout.

🎯 Goals

Zero-downtime rollout, <5 minute rollback, and a verified green run on the canary before any production gate is switched on.

🔄 Key Insight

The checker is stdlib-only, so deployment is a single immutable image — no dependency resolution at runtime.

📚 Audience

Release engineers running the promotion, and repo owners who consume the CI gate.

⚠️
Precondition: canary must be green first
Do not promote to the production registry until the canary repo reports a green check. Promoting early risks gating every embedded repo on an unvalidated build.
🔧 Environment Setup

1. Authenticate & pull sources

git clone git@repo:misrac-checker.git
cd misrac-checker
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt

2. Build & tag the release image

docker build -t registry/misrac-checker:2.1.0 .
docker push registry/misrac-checker:2.1.0

3. Run on the canary repo

python main.py --canary embedded/ecu-core
pytest tests/ -q

🏗️ 3 · Architecture
Deployment topology and where the checker runs
🧩 Deployment Components
Registry
  • Holds the immutable misrac-checker:2.1.0 image
  • Previous tag kept for instant rollback
CI Runner
  • Pulls the pinned image and runs main.py
  • Stateless — no local dependency install
Repo Gate
  • Consumes HTML/JSON artifacts as a merge gate
  • Blocks on mandatory-severity violations
Canary
  • embedded/ecu-core validates before fleet rollout
  • Green run is the promotion gate
PAIN
Manual MISRA gating was inconsistent and not reproducible across repos.
▼
ROOT
No single, versioned checker artifact shared by all pipelines.
▼
IMPACT
Compliance could not be enforced uniformly at merge time.
▼
ACTION
A pinned, immutable image deployed via CI provides a deterministic, auditable gate.
